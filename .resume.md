## Architecture Notes

### Database API Pattern
`Database` exposes two closure-based APIs:
```rust
db.write(|conn| { ... Ok(value) })?;  // mutable operations
db.read(|conn| { ... Ok(value) })?;   // read-only operations
```
`get_conn()` shim is ONLY safe in sync functions (no `.await` after). All async functions MUST use the closure pattern — `MutexGuard: !Send` prevents holding it across await points.

### Agent Re-entrant Pattern
Agent does NOT run as a background task. Flow:
1. `start_agent_run` → plans steps → writes `pending` steps to DB → starts `execute_steps`
2. `execute_steps` → processes steps → if approval needed → sets step `awaiting_approval` → returns
3. Frontend polls/resumes → user approves → `resume_agent_run` → continues from that step
4. Each step result is written to DB in real time

### FTS5 Security
`sanitize_fts_query()` strips special chars and wraps each word in double-quotes to prevent FTS5 injection. Max 20 words per query.

### MCP Path Security
`validate_path_access()` calls `std::fs::canonicalize()` on BOTH the requested path and each allowed path — prevents symlink traversal. If path doesn't exist yet, canonicalizes parent directory instead.

# AIFlow — 인시던트 대응 계획 v4.0

> 생성: 2026-03-30 (v4.0)
> GDPR 제33조 72시간 통지 의무 + PIPA 지체없이 통지 의무 충족을 위한 대응 절차

---

## 1. 인시던트 분류

| 등급 | 정의 | 예시 | 대응 시간 |
|------|------|------|----------|
| **CRITICAL** | API 키 또는 DB 마스터키 유출 | 키체인 취약점, 업데이트 서버 해킹 | **즉시** (1시간 내 초동 대응) |
| **HIGH** | 사용자 대화 데이터 유출 | DB 파일 유출 (SQLCipher 미암호화 버그) | **4시간 내** |
| **MEDIUM** | 사용 패턴/비용 정보 노출 | 분석 데이터 유출, Sentry PII 필터 누락 | **24시간 내** |
| **LOW** | 비민감 데이터 노출 | 앱 버전, OS 정보 노출 | **72시간 내** |

---

## 2. 대응 타임라인

### GDPR (72시간 규칙)
1. **0~1시간**: 인시던트 확인 + 영향 범위 파악
2. **1~4시간**: 긴급 패치 배포 (자동 업데이터) 또는 기능 비활성화
3. **4~24시간**: 영향받은 사용자 파악 + 알림 초안 작성
4. **24~72시간**: 감독기관 통지 (EU 사용자가 있는 경우)

### PIPA (지체없이)
- 한국 사용자 데이터가 포함된 경우, 개인정보보호위원회에 **지체 없이** 통지
- "지체 없이"는 실무적으로 **72시간 이내** 해석

## 3. 자동 대응 메커니즘

### API 키 노출 시
```
1. 앱 내 긴급 알림: "보안 이슈가 감지되었습니다. 모든 API 키를 즉시 교체하세요."
2. 설정 → "API 키 비상 삭제" 원클릭 실행 안내
3. AI 프로바이더 키 폐기 직접 링크 표시:
   - OpenAI: platform.openai.com/api-keys
   - Anthropic: console.anthropic.com/api-keys
   - Google: aistudio.google.com/app/apikey
4. 감사 로그에 "security_incident_api_key_exposure" 이벤트 기록
```

### 업데이터 서버 해킹 시
```
1. Ed25519 서명 불일치 → 업데이트 자동 거부 (사용자에게 알림)
2. 수동 다운로드 안내 (공식 GitHub Releases 링크)
3. 서버 측: 해킹된 업데이트 즉시 제거 + 서명 키 로테이션
```

## 4. 사용자 알림 채널

| 채널 | 도달 범위 | 적용 시점 |
|------|----------|----------|
| **앱 내 알림** (가장 우선) | 앱 실행 중인 사용자 | 즉시 |
| **GitHub Security Advisory** | GitHub 팔로워 | 24시간 내 |
| **공식 웹사이트 공지** | 검색 유입 사용자 | 24시간 내 |
| **이메일** (수집 시) | Pro 구독자 | 48시간 내 |

---

## 5. 포렌식 보존 정책

- 인시던트 발생 시 **감사 로그 삭제 금지** (보존 기간 자동 삭제 일시 중단)
- 영향받은 DB 백업 파일 별도 보관 (분석용)
- 타임라인 기록: 발견 시점, 영향 범위, 조치 내역, 완료 시점

---

## 6. 사후 조치

1. **근본 원인 분석** (Root Cause Analysis) 문서 작성
2. **재발 방지 대책** PRD/보안 명세에 반영
3. **보안 패치** 자동 업데이터로 즉시 배포
4. **투명성 보고서** (분기별, 인시던트 유무와 관계없이 발행)
